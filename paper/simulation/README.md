# VisionAI reflex simulations

Every figure and quoted number in the paper's Results section is generated by the
three scripts in this directory. A slide-by-slide walkthrough is in
[`../VisionAI_Simulation_Replication.pptx`](../VisionAI_Simulation_Replication.pptx).

## What this is

The ML Kit detector runs only on Android, so it is **not** simulated. Instead the
app's *decision layer* is ported to Python line for line, keeping every shipped
constant, and is fed synthetic bounding boxes generated from pinhole camera
geometry with noise added. These studies therefore test whether the decision
logic does the right thing **given a detection** — not whether the camera sees
the obstacle.

Simulated camera: 60° vertical and 46° horizontal field of view, 10 fps, walker
at 1.4 m/s. Box dimensions carry 10% multiplicative noise and box centres 3%
positional noise.

## Requirements

Python 3 with `numpy` and `matplotlib`. Nothing else — no API keys, no Android
device, no network.

```bash
pip install numpy matplotlib
```

## Running

`sim_extra.py` and `sim_baselines.py` import `sim_reflex`, so run them **from
inside this directory**.

```bash
python3 sim_reflex.py && python3 sim_extra.py && python3 sim_baselines.py
```

| Script | Time | Produces |
|---|---|---|
| `sim_reflex.py` | ~2 s | `fig1`–`fig6`, `sim_results.json` |
| `sim_extra.py` | ~5 s | envelope, speed, sweep, flicker, hint-outcome, cadence figures, `sim_extra_results.json` |
| `sim_baselines.py` | ~2 s | `fig_baselines.png`, `sim_baseline_results.json` |

All seeds are fixed. A clean re-run reproduces all 13 PNGs and all 3 JSON files
byte-identically, verified with `cmp`.

## Study protocol (the one reported in the paper)

**Scene model.** Each scene draws an obstacle height (0.3–1.9 m), width
(0.15–0.9 m), distance (0.8–9 m), and lateral offset (±2.5 m), plus a hand-held
camera pitch between 10° up and 30° down and a camera height of 1.3 m ± 0.08.
A quarter of scenes contain only a distant wall or fence. Apparent box size
follows pinhole projection. **A scene counts as a hazard when the object lies in
the walking path (±0.45 m) within 2.5 m.**

**Sampling.** False-alarm and miss rates are estimated on separate stratified
draws — 16,000 hazard-free scenes and 8,000 hazard scenes — so both rates rest on
adequate support. Every rule receives the identical trailing 0.9 s of
observations, so none is advantaged by information the others lack.

**Pitch stability.** The same scene is re-evaluated with pitch perturbed ±8°
while the detector noise realisation is held fixed, so the measure isolates pitch
sensitivity rather than noise.

### The five decision rules compared (paper Fig. 3)

| Rule | Criterion |
|---|---|
| R1 | Optical time-to-contact alone (Lee 1976), τ ≤ 2 s, **no spatial gate** |
| R2 | Fixed apparent-size threshold alone, height ≥ 0.34 of frame |
| R3 | Ground-contact bottom-edge heuristic (also our first prototype) |
| R4 | Idealised monocular relative depth (MiDaS-style), with scale ambiguity and ground-plane confusion modelled |
| R5 | **Shipped rule** — corridor gate, background-width rejection, size gates, looming, 2-frame confirmation |

R1–R4 are reimplementations of published *criteria* under the assumptions above.
They are **not** reimplementations of any product, and no claim is made about how
any deployed system performs.

## Extending

Thresholds are module-level constants, and the scoring harness is parameterised,
so a sweep is a loop rather than an edit:

```python
import numpy as np, sim_extra as sx

rng = np.random.default_rng(23)
for gate in [0.26, 0.34, 0.46]:
    fa, miss = sx.eval_rule(rng, near_h=gate)
    print(gate, round(fa, 2), round(miss, 1))
```

Useful entry points: `frame_danger` (one-frame verdict), `eval_rule` (error rates
for a rule), and the `RULES` list in `sim_baselines.py` — append a function and a
row there to add a new comparator and the harness picks it up automatically.

## Limits

These results establish that the decision layer behaves as designed and that the
comparisons are exactly reproducible. They do **not** establish that the detector
boxes the obstacle at all, how the system behaves under real lighting, motion
blur, or hardware variation, or anything about safety for a real traveller.
Camera geometry, frame rate, and walking speed are stated assumptions rather than
measurements.
